## 1. Purpose & Scope

### 1.1 What This Guide Produces

This guide specifies how to build a fully automated pipeline that:

1. **Generates** a Traceability Matrix (TM) mapping every requirement ID → the source code function(s) that implement it, using an enterprise LLM API.
2. **Maintains** the TM incrementally — any time a requirement document or source file changes, only the affected mappings are re-evaluated. The full LLM re-run is never repeated for unchanged content.
3. **Flags unmapped requirements** — requirements that have no implementation in the codebase are separated into an `Unmapped-Requirements.md` file with a reason generated by the LLM.
4. **Validates** TM integrity — `|TM rows| + |Unmapped rows| == |Total requirements|` is enforced automatically.

### 1.2 Scope — General Purpose Design

The pipeline is deliberately general-purpose. It is not tied to AUTOSAR, CanIf, C language, or any specific domain. You configure it via `tm_config.yaml` and it works for:

- Any requirement format: CSV, Excel, DOORS HTML export, plain text, JSON
- Any source language: C, C++, Python, Java, Go (via configurable parsers)
- Any naming convention for requirement IDs: `SWS_CANIF_xxxxx`, `REQ-xxx`, `JIRA-xxx`, custom regex
- Any number of source files, modules, or repositories

### 1.3 Relationship to the SDLC AI Project

This pipeline implements two capabilities defined in the project document:

| SDLC Category | Capability | This Pipeline's Role |
|:---|:---|:---|
| **Category 2 — Implementation** | Code Traceability Check | Generates the TM (req → function mapping) |
| **Category 2 — Implementation** | Propose Changes Due to Requirements Change | The TM is consumed by the Impact Analyzer to find which functions are affected by a changed requirement |

The TM is the **shared artifact** between the traceability sub-system and the change-propagation sub-system. Every other downstream AI module (impact analyzer, test case generator, code review) reads from this TM.

### 2.1 Two Operating Modes

| Mode | Trigger | Behavior |
|:---|:---|:---|
| **Full Generation** | First run, or `--full` flag | Parse all reqs + all functions. Run LLM on every req. Write fresh TM from scratch. |
| **Incremental Update** | File change detected (git hook / CI) | Parse only changed files. Re-run LLM only for changed reqs and functions affected by code changes. Merge results into existing TM. |

## 4. Step 1 — Requirements Parser

### 4.1 Goal

Produce a normalized list of requirement objects from any input format:

```python
[
  { "id": "SWS_CANIF_00308", "description": "The service CanIf_SetControllerMode() shall call Can_SetControllerMode(...)..." },
  { "id": "SWS_CANIF_00311", "description": "If parameter ControllerId of CanIf_SetControllerMode() has an invalid value..." },
  ...
]
```

### 4.2 Supported Input Formats

#### Format A — CSV with ID and Description columns

Config:
```yaml
requirements:
  format: csv
  file: "Requirments/CanIf_SWS_AR403.csv"
  id_column: "RequirementID"        # exact column header
  description_column: "Description" # exact column header
  id_pattern: "SWS_\\w+_\\d+"       # regex to validate ID format (optional)
```

Parser logic:
```python
import pandas as pd
import re

def parse_requirements_csv(config):
    df = pd.read_csv(config["file"], encoding="utf-8")
    reqs = []
    for _, row in df.iterrows():
        req_id = str(row[config["id_column"]]).strip()
        desc   = str(row[config["description_column"]]).strip()
        if config.get("id_pattern") and not re.match(config["id_pattern"], req_id):
            continue  # skip header rows or non-req rows
        reqs.append({"id": req_id, "description": desc})
    return reqs
```

#### Format B — Excel (.xlsx)

Config:
```yaml
requirements:
  format: excel
  file: "requirements.xlsx"
  sheet: "Requirements"
  id_column: "Req ID"
  description_column: "Description"
```

Parser logic: identical to CSV, replace `pd.read_csv` with `pd.read_excel(sheet_name=config["sheet"])`.

#### Format C — DOORS HTML Export

DOORS exports requirements as HTML tables. Parse with `BeautifulSoup`:

```python
from bs4 import BeautifulSoup

def parse_requirements_doors_html(config):
    with open(config["file"], encoding="utf-8") as f:
        soup = BeautifulSoup(f, "html.parser")
    reqs = []
    for row in soup.find_all("tr"):
        cells = row.find_all("td")
        if len(cells) >= 2:
            req_id = cells[config["id_col_index"]].get_text(strip=True)
            desc   = cells[config["desc_col_index"]].get_text(strip=True)
            if re.match(config["id_pattern"], req_id):
                reqs.append({"id": req_id, "description": desc})
    return reqs
```

#### Format D — Plain Text (one req per line, `ID: description`)

Config:
```yaml
requirements:
  format: plain_text
  file: "requirements.txt"
  line_pattern: "^(\\S+):\\s+(.+)$"  # group 1 = ID, group 2 = description
```

#### Format E — JSON

Config:
```yaml
requirements:
  format: json
  file: "requirements.json"
  id_field: "id"
  description_field: "text"
```

### 4.3 Requirements Parser — Master Dispatcher

```python
def parse_requirements(config):
    fmt = config["requirements"]["format"]
    dispatch = {
        "csv":        parse_requirements_csv,
        "excel":      parse_requirements_excel,
        "doors_html": parse_requirements_doors_html,
        "plain_text": parse_requirements_plain_text,
        "json":       parse_requirements_json,
    }
    if fmt not in dispatch:
        raise ValueError(f"Unsupported requirements format: {fmt}")
    return dispatch[fmt](config["requirements"])
```

### 4.4 Output

Each requirement object in the output list must contain at minimum:

| Field | Type | Description |
|:---|:---|:---|
| `id` | `str` | The unique requirement identifier |
| `description` | `str` | Full requirement text |
| `hash` | `str` | SHA-256 of `id + description` — used by change detector |

```python
import hashlib

def add_hashes(reqs):
    for r in reqs:
        r["hash"] = hashlib.sha256((r["id"] + r["description"]).encode()).hexdigest()[:16]
    return reqs
```

## 5. Step 2 — Source Code Parser

### 5.1 Goal

Produce a normalized list of function objects from all source files:

```python
[
  {
    "name":       "CanIf_SetControllerMode",
    "file":       "CanIf.c",
    "line_start": 226,
    "line_end":   320,
    "signature":  "Std_ReturnType CanIf_SetControllerMode(uint8 Controller, CanIf_ControllerModeType ControllerMode)",
    "body_text":  "... full function body as string ...",
    "comments":   "/* comment text extracted from inside the function */",
    "hash":       "a3b9c2f1"
  },
  ...
]
```

### 5.2 Tree-sitter Parser (Recommended — Accurate AST)

Tree-sitter builds a proper Abstract Syntax Tree. It handles macros, nested blocks, `#ifdef` guards, and complex C constructs that regex cannot.

```python
from tree_sitter import Language, Parser
import tree_sitter_c as tsc

C_LANGUAGE = Language(tsc.language())

def extract_functions_c(filepath):
    parser = Parser(C_LANGUAGE)
    with open(filepath, "rb") as f:
        source = f.read()
    tree = parser.parse(source)
    functions = []
    _walk_for_functions(tree.root_node, source, filepath, functions)
    return functions

def _walk_for_functions(node, source, filepath, results):
    if node.type == "function_definition":
        fn = _extract_function_node(node, source, filepath)
        results.append(fn)
    for child in node.children:
        _walk_for_functions(child, source, filepath, results)

def _extract_function_node(node, source, filepath):
    start_line = node.start_point[0] + 1  # tree-sitter is 0-indexed
    end_line   = node.end_point[0] + 1
    body_bytes = source[node.start_byte:node.end_byte]
    body_text  = body_bytes.decode("utf-8", errors="replace")

    # extract function name from declarator
    name = ""
    for child in node.children:
        if child.type == "function_declarator":
            for sub in child.children:
                if sub.type == "identifier":
                    name = source[sub.start_byte:sub.end_byte].decode()
                    break

    # extract signature (everything up to the opening brace)
    sig_end = body_text.find("{")
    signature = body_text[:sig_end].strip().replace("\n", " ")

    return {
        "name":       name,
        "file":       filepath,
        "line_start": start_line,
        "line_end":   end_line,
        "signature":  signature,
        "body_text":  body_text,
        "comments":   _extract_comments_from_body(body_text),
        "hash":       hashlib.sha256(body_text.encode()).hexdigest()[:16],
    }
```

**Comments extraction** (separate step — comments often contain inline requirement references like `/* SWS_CANIF_00308 */`):

```python
import re

def _extract_comments_from_body(body_text):
    block_comments = re.findall(r'/\*.*?\*/', body_text, re.DOTALL)
    line_comments  = re.findall(r'//[^\n]*', body_text)
    all_comments   = block_comments + line_comments
    return " ".join(c.strip() for c in all_comments)
```

### 5.4 Python and Java Parsers (Brief)

**Python** — use the built-in `ast` module:

```python
import ast

def extract_functions_python(filepath):
    with open(filepath, encoding="utf-8") as f:
        source = f.read()
    tree = ast.parse(source)
    functions = []
    for node in ast.walk(tree):
        if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
            functions.append({
                "name":       node.name,
                "file":       filepath,
                "line_start": node.lineno,
                "line_end":   node.end_lineno,
                "signature":  f"def {node.name}(...)",
                "body_text":  ast.get_source_segment(source, node) or "",
                "comments":   ast.get_docstring(node) or "",
                "hash":       hashlib.sha256((ast.get_source_segment(source, node) or "").encode()).hexdigest()[:16],
            })
    return functions
```

**Java** — use regex as a reasonable fallback (tree-sitter-java is also available):

```python
JAVA_FN_PATTERN = re.compile(
    r'(?:public|private|protected|static|\s)+[\w<>\[\]]+\s+(\w+)\s*\([^)]*\)\s*(?:throws\s+\w+\s*)?\{',
    re.MULTILINE
)
```

### 5.5 Inline Requirement References (Bonus Pass)

Many AUTOSAR C files include inline comments citing the requirement IDs that justify a code block (e.g., `/* SWS_CANIF_00308 */`). The parser should extract these as a **strong mapping signal** before the LLM even runs:

```python
def extract_inline_req_refs(body_text, id_pattern):
    return re.findall(id_pattern, body_text)
```

If `inline_refs` for a function contains a req ID, that mapping is already very likely correct. Flag it for the LLM as pre-evidence.

## 6. Step 3 — LLM-Based Traceability Mapping

### 6.1 Strategy Overview

Calling the LLM on every (req, function) pair is prohibitively expensive — for 273 requirements and 50 functions that is 13,650 API calls. The strategy is a **two-pass hybrid**:

```
Pass 1 — Embedding Shortlist (fast, cheap)
  ├── Embed every requirement description (batch call)
  ├── Embed every function's [signature + comments + body_text excerpt]
  └── For each req: cosine-rank all functions → keep top-K (K = 8 by default)

Pass 2 — LLM Reasoning (targeted, accurate)
  ├── For each req: build a prompt with the req + its top-K function candidates
  ├── Ask LLM: "Which of these functions implement this requirement? Or none?"
  └── LLM returns: list of function names + confidence (HIGH/MEDIUM/LOW) + reason
```

This reduces LLM calls from O(reqs × functions) to O(reqs × 1).

### 6.2 Pass 1 — Embedding Shortlist

**What to embed for each function:**

Concatenate the most informative parts. Limit to ~400 tokens to keep embeddings cheap:

```python
def build_function_embedding_text(fn, max_chars=1500):
    parts = [
        f"Function: {fn['name']}",
        f"Signature: {fn['signature']}",
        f"File: {fn['file']}",
    ]
    if fn["comments"]:
        parts.append(f"Comments: {fn['comments'][:300]}")
    # include first 600 chars of body (entry point logic is most req-relevant)
    parts.append(f"Body (excerpt): {fn['body_text'][:600]}")
    return "\n".join(parts)[:max_chars]
```

**Embedding API call (Anthropic):**

As of 2025, use `claude-3-haiku-20240307` for embeddings (cheapest and fastest):

```python
import anthropic
import numpy as np

client = anthropic.Anthropic(api_key=os.environ["TM_LLM_API_KEY"])

def get_embeddings_batch(texts: list[str]) -> list[list[float]]:
    # Anthropic does not expose a direct embeddings endpoint as of this writing.
    # Use voyage-3-lite via Anthropic partner API, or switch to OpenAI embeddings.
    # For OpenAI-compatible:
    from openai import OpenAI
    oai = OpenAI(api_key=os.environ["TM_LLM_API_KEY"], base_url=os.environ.get("TM_LLM_BASE_URL"))
    response = oai.embeddings.create(model="text-embedding-3-small", input=texts)
    return [item.embedding for item in response.data]
```

> **Note for enterprise LLM:** If your enterprise API does not expose an embeddings endpoint,
> skip Pass 1 entirely and use a simple TF-IDF keyword overlap as the shortlist instead
> (see Section 6.2.1 below). Pass 2 (LLM reasoning) is the authoritative decision maker anyway.

**6.2.1 Fallback: TF-IDF Shortlist (no embeddings needed)**

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

def tfidf_shortlist(req_desc, function_texts, top_k=8):
    corpus = [req_desc] + function_texts
    vectorizer = TfidfVectorizer(stop_words="english")
    tfidf_matrix = vectorizer.fit_transform(corpus)
    scores = cosine_similarity(tfidf_matrix[0:1], tfidf_matrix[1:]).flatten()
    top_indices = scores.argsort()[::-1][:top_k]
    return top_indices.tolist()
```

### 6.3 Pass 2 — LLM Reasoning

For each requirement, build a prompt containing:
- The requirement ID and full description
- The top-K candidate functions (name + signature + first 400 chars of body)
- Any inline references found in Step 2.5
- Clear, structured instructions for the output format

#### 6.3.1 Prompt Template

```python
SYSTEM_PROMPT = """You are a software traceability expert for AUTOSAR embedded systems.
Your task is to determine which C functions in a source file implement a given software requirement.

Rules:
1. A function "implements" a requirement if the requirement's behavioral constraint is directly
   enforced by logic inside that function — not just indirectly called.
2. A requirement may be implemented by multiple functions (list all of them).
3. A requirement is "UNMAPPED" if none of the candidate functions implement it, or if the
   requirement describes a feature/configuration that has no corresponding function in this module.
4. Return ONLY a valid JSON object. No explanation outside the JSON.

Output format:
{
  "req_id": "<requirement ID>",
  "status": "MAPPED" | "UNMAPPED",
  "mappings": [
    {
      "function": "<function name>",
      "confidence": "HIGH" | "MEDIUM" | "LOW",
      "reason": "<one sentence explaining why this function implements the requirement>"
    }
  ],
  "unmapped_reason": "<if UNMAPPED: one sentence explaining why no function implements this req>"
}
"""

def build_user_prompt(req, candidates, inline_refs):
    lines = [
        f"REQUIREMENT ID: {req['id']}",
        f"REQUIREMENT TEXT: {req['description']}",
        "",
    ]
    if inline_refs:
        lines.append(f"NOTE: This req ID was found as an inline comment in functions: {', '.join(inline_refs)}")
        lines.append("")
    lines.append("CANDIDATE FUNCTIONS:")
    for i, fn in enumerate(candidates, 1):
        body_excerpt = fn["body_text"][:400].replace("\n", " ")
        lines.append(f"\n[Candidate {i}] {fn['name']} ({fn['file']}:{fn['line_start']})")
        lines.append(f"  Signature: {fn['signature']}")
        if fn["comments"]:
            lines.append(f"  Comments: {fn['comments'][:200]}")
        lines.append(f"  Body (excerpt): {body_excerpt}...")
    lines.append("\nWhich of these functions implement the requirement? Return JSON only.")
    return "\n".join(lines)
```

#### 6.3.2 API Call (Anthropic Claude)

```python
import json

def call_llm_for_mapping(req, candidates, inline_refs, config):
    user_prompt = build_user_prompt(req, candidates, inline_refs)

    response = client.messages.create(
        model=config["llm"]["model"],          # e.g. "claude-sonnet-4-6"
        max_tokens=1024,
        system=SYSTEM_PROMPT,
        messages=[{"role": "user", "content": user_prompt}],
    )

    raw = response.content[0].text.strip()

    # Strip markdown code fences if the model adds them
    if raw.startswith("```"):
        raw = re.sub(r"^```(?:json)?\n?", "", raw)
        raw = re.sub(r"\n?```$", "", raw)

    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        # Fallback: return UNMAPPED with error note
        return {
            "req_id": req["id"],
            "status": "UNMAPPED",
            "mappings": [],
            "unmapped_reason": f"LLM returned non-JSON response. Manual review required. Raw: {raw[:200]}"
        }
```

#### 6.3.3 API Call (OpenAI / Azure OpenAI)

```python
from openai import OpenAI

oai_client = OpenAI(
    api_key=os.environ["TM_LLM_API_KEY"],
    base_url=os.environ.get("TM_LLM_BASE_URL", "https://api.openai.com/v1"),
)

def call_llm_for_mapping_openai(req, candidates, inline_refs, config):
    user_prompt = build_user_prompt(req, candidates, inline_refs)
    response = oai_client.chat.completions.create(
        model=config["llm"]["model"],    # e.g. "gpt-4o"
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user",   "content": user_prompt},
        ],
        response_format={"type": "json_object"},  # force JSON output
        max_tokens=1024,
    )
    raw = response.choices[0].message.content
    return json.loads(raw)
```

### 6.4 Confidence Scoring Rules

The LLM returns `HIGH`, `MEDIUM`, or `LOW`. Post-process to apply the following rules automatically:

| Condition | Confidence Adjustment |
|:---|:---|
| Req ID appears as inline comment inside the function body | Upgrade to `HIGH` (override LLM) |
| Function name contains the AUTOSAR service name from the req text | Upgrade to `HIGH` if LLM said `MEDIUM` |
| LLM returned `LOW` and no other mapping exists | Flag for manual review |
| LLM returned `UNMAPPED` but inline ref exists | Flag as conflict — require manual resolution |

```python
def apply_confidence_rules(result, req, all_functions_by_name):
    fn_inline_refs = {}
    for fn in all_functions_by_name.values():
        refs = extract_inline_req_refs(fn["body_text"], config["requirements"]["id_pattern"])
        for ref_id in refs:
            fn_inline_refs.setdefault(ref_id, []).append(fn["name"])

    if req["id"] in fn_inline_refs:
        inline_fns = fn_inline_refs[req["id"]]
        for mapping in result["mappings"]:
            if mapping["function"] in inline_fns:
                mapping["confidence"] = "HIGH"
                mapping["reason"] += " [Confirmed by inline comment reference]"

    return result
```

### 6.5 Handling Rate Limits

Enterprise APIs have rate limits. Add exponential backoff:

```python
import time

def call_llm_with_retry(req, candidates, inline_refs, config, max_retries=3):
    for attempt in range(max_retries):
        try:
            return call_llm_for_mapping(req, candidates, inline_refs, config)
        except Exception as e:
            if "rate_limit" in str(e).lower() or "429" in str(e):
                wait = 2 ** attempt * 5  # 5s, 10s, 20s
                print(f"  Rate limit hit. Waiting {wait}s...")
                time.sleep(wait)
            else:
                raise
    raise RuntimeError(f"LLM call failed after {max_retries} retries for req {req['id']}")
```

### 6.6 Full Mapping Loop

```python
def run_mapping(reqs, functions, config):
    # Build shortlist
    function_texts = [build_function_embedding_text(fn) for fn in functions]
    fn_by_index = {i: fn for i, fn in enumerate(functions)}

    results = []
    for req in reqs:
        # Shortlist
        candidate_indices = tfidf_shortlist(req["description"], function_texts, top_k=config["llm"]["shortlist_k"])
        candidates = [fn_by_index[i] for i in candidate_indices]

        # Inline refs
        inline_fns = [fn["name"] for fn in functions
                      if req["id"] in extract_inline_req_refs(fn["body_text"], config["requirements"]["id_pattern"])]

        # Include functions with inline refs even if not in top-K
        inline_fn_objects = [fn for fn in functions if fn["name"] in inline_fns and fn not in candidates]
        candidates = candidates + inline_fn_objects

        # LLM decision
        result = call_llm_with_retry(req, candidates, inline_fns, config)
        result = apply_confidence_rules(result, req, {fn["name"]: fn for fn in functions})
        results.append(result)

        print(f"  [{req['id']}] → {result['status']}: {[m['function'] for m in result['mappings']]}")

    return results
```

## 8. Step 5 — Incremental Update System

### 8.1 Why Incremental?

A full re-run for 273 requirements × LLM calls takes minutes and costs API credits. In practice, a typical change affects 1–5 requirements and 1–3 source functions. The incremental system runs in seconds and spends credits only on what changed.

### 8.2 Change Detection Algorithm

```python
def detect_changes(reqs, functions, state):
    changes = {
        "new_reqs":      [],   # req IDs not in state at all
        "modified_reqs": [],   # req IDs whose hash changed
        "deleted_reqs":  [],   # req IDs in state but not in current reqs
        "modified_fns":  [],   # function names whose hash changed
        "new_fns":       [],   # function names not in state at all
        "deleted_fns":   [],   # function names in state but not in current code
    }

    current_req_ids = {r["id"] for r in reqs}
    current_fn_names = {f["name"] for f in functions}

    for req in reqs:
        old_hash = state["req_hashes"].get(req["id"])
        if old_hash is None:
            changes["new_reqs"].append(req["id"])
        elif old_hash != req["hash"]:
            changes["modified_reqs"].append(req["id"])

    for fn in functions:
        old_hash = state["fn_hashes"].get(fn["name"])
        if old_hash is None:
            changes["new_fns"].append(fn["name"])
        elif old_hash != fn["hash"]:
            changes["modified_fns"].append(fn["name"])

    for req_id in state["req_hashes"]:
        if req_id not in current_req_ids:
            changes["deleted_reqs"].append(req_id)

    for fn_name in state["fn_hashes"]:
        if fn_name not in current_fn_names:
            changes["deleted_fns"].append(fn_name)

    return changes
```

### 8.3 Which Requirements Need Re-mapping?

```python
def compute_reqs_to_remap(changes, state):
    reqs_to_remap = set()

    # Directly changed reqs
    reqs_to_remap.update(changes["new_reqs"])
    reqs_to_remap.update(changes["modified_reqs"])

    # If a function changed, all reqs that were mapped to it must be re-evaluated
    affected_by_fn_change = set()
    for fn_name in changes["modified_fns"] + changes["deleted_fns"]:
        for req_id, mapped_fns in state["tm"].items():
            if fn_name in mapped_fns:
                affected_by_fn_change.add(req_id)
    reqs_to_remap.update(affected_by_fn_change)

    # New functions need to be offered to ALL existing reqs as a new candidate
    # This is expensive — only do it if new function names suggest new functionality
    # (heuristic: skip if new function is a helper/static/private)
    for fn_name in changes["new_fns"]:
        if not fn_name.startswith("_") and not fn_name.endswith("_internal"):
            # Public API function added — potentially relevant to many reqs
            # Re-map all reqs that are currently UNMAPPED (low cost: unmapped shortlist)
            reqs_to_remap.update(state["unmapped"].keys())

    return reqs_to_remap
```

### 8.4 Incremental Run Loop

```python
def run_incremental(reqs, functions, state, config):
    changes = detect_changes(reqs, functions, state)

    if not any(changes.values()):
        print("No changes detected. TM is up to date.")
        return state  # nothing to do

    reqs_to_remap = compute_reqs_to_remap(changes, state)
    print(f"Incremental update: {len(reqs_to_remap)} requirements to re-evaluate.")

    reqs_dict = {r["id"]: r for r in reqs}
    subset_reqs = [reqs_dict[req_id] for req_id in reqs_to_remap if req_id in reqs_dict]

    # Run LLM only for the subset
    new_results = run_mapping(subset_reqs, functions, config)

    # Handle deleted requirements
    for req_id in changes["deleted_reqs"]:
        state["tm"].pop(req_id, None)
        state["unmapped"].pop(req_id, None)
        state["req_hashes"].pop(req_id, None)

    # Merge new results into state
    for result in new_results:
        req_id = result["req_id"]
        if result["status"] == "MAPPED":
            state["tm"][req_id] = [m["function"] for m in result["mappings"]]
            state["unmapped"].pop(req_id, None)
        else:
            state["unmapped"][req_id] = result.get("unmapped_reason", "")
            state["tm"].pop(req_id, None)

    # Update hashes in state
    for req in reqs:
        state["req_hashes"][req["id"]] = req["hash"]
    for fn in functions:
        state["fn_hashes"][fn["name"]] = fn["hash"]

    state["last_run"] = datetime.now().isoformat()
    return state
```

### 9.1 Git Pre-commit Hook

Runs automatically every time a developer commits changes to requirement files or source files.

**File:** `.git/hooks/pre-commit`

```bash
#!/bin/bash
# TM Auto-Update Pre-commit Hook

CHANGED_FILES=$(git diff --cached --name-only)
REQ_PATTERN=".*\.(csv|xlsx|txt|json)$"
SRC_PATTERN=".*\.(c|cpp|h|py|java)$"

NEEDS_TM_UPDATE=false

for f in $CHANGED_FILES; do
    if echo "$f" | grep -qE "$REQ_PATTERN|$SRC_PATTERN"; then
        NEEDS_TM_UPDATE=true
        break
    fi
done

if [ "$NEEDS_TM_UPDATE" = true ]; then
    echo "Traceability-relevant files changed. Running incremental TM update..."
    python tm_pipeline/main.py --mode incremental --config tm_config.yaml

    if [ $? -ne 0 ]; then
        echo "ERROR: TM update failed. Commit blocked. Fix the issue and retry."
        exit 1
    fi

    # Stage the updated TM files so they're included in the commit
    git add REQ-CODE-TM.md Unmapped-REQ.md tm_state.json tm_report.json
    echo "TM updated and staged."
fi

exit 0
```

## 12. End-to-End Workflow Summary

### First Run (Full Generation)

```
1. Engineer sets up tm_config.yaml (requirements file path, source dirs, LLM model)
2. Engineer sets TM_LLM_API_KEY env var
3. Run: python tm_pipeline/main.py --mode full --config tm_config.yaml

Pipeline executes:
  ├── requirements_parser.py  → list of 273 {id, description, hash}
  ├── code_parser.py          → list of N {name, signature, body, hash}
  ├── llm_mapper.py
  │     ├── TF-IDF shortlist: for each req → top-8 function candidates
  │     ├── For each req: LLM API call → {status, mappings, confidence}
  │     └── Confidence post-processing (inline ref upgrade)
  ├── output_generator.py
  │     ├── write REQ-CODE-TM.md
  │     ├── write Unmapped-REQ.md
  │     ├── write tm_report.json
  │     └── write tm_state.json (initial state)
  └── validate.py → assert mapped + unmapped == 273 ✓
```

### Ongoing Updates (Incremental)

```
Trigger: git pre-commit hook OR CI push OR watcher.py

Pipeline executes:
  ├── requirements_parser.py  → re-parse ALL reqs (fast — just file reading)
  ├── code_parser.py          → re-parse ALL source files (fast — just file reading)
  ├── change_detector.py      → compare hashes to tm_state.json
  │     → produces: changed_reqs[], changed_functions[]
  ├── llm_mapper.py (SUBSET ONLY)
  │     → run LLM only for changed_reqs + reqs affected by fn changes
  ├── output_generator.py     → MERGE new results into existing TM, rewrite files
  └── validate.py             → assert count integrity ✓
```

### Review Queue (Human in the Loop)

```
After any run:
  tm_review_queue.md lists all LOW-confidence mappings.
  An engineer reviews these and either:
    (a) accepts → edit tm_state.json to upgrade confidence to MEDIUM/HIGH
    (b) rejects → add to a manual override list in tm_config.yaml
```

## 13. Quality Validation Checklist

Run `python tm_pipeline/validate.py` after every generation. It checks:

| Check | Method | Pass Condition |
|:---|:---|:---|
| **Count Integrity** | `len(tm) + len(unmapped) == len(all_reqs)` | Exact match — no missing or duplicate IDs |
| **No Duplicate Req IDs** | Set check on all req IDs | Each ID appears exactly once across TM + Unmapped |
| **No Phantom Mappings** | Every function in TM must exist in parsed code | No function name in TM that has no matching function object |
| **No Empty Mappings** | No TM row with zero functions | Every mapped req has at least one function |
| **Confidence Coverage** | Count LOW-confidence mappings | Report percentage; alert if > 10% |
| **Stale State** | `state["last_run"]` vs. most recent file mtime | Warn if state is older than the source files by > 24h |
| **Inline Ref Consistency** | For every inline comment `/* REQ_ID */` in code | The req must be in TM mapped to that function |
